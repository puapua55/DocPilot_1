# DocPilot AI 문서 인식형 챗봇 테스트 체크리스트

## 공통
- [ ] 문서 없이 일반 질문 가능
- [ ] API 오류 시 에러 메시지 표시
- [ ] API Key가 프론트엔드에 노출되지 않음
- [ ] 채팅 전송 로그에는 문서명/유형/길이만 남고 문서 전문은 남지 않음

## PDF
- [ ] PDF 업로드 후 `documentTextLength > 0`
- [ ] 추출 텍스트에 `[1페이지]`, `[2페이지]` 등 페이지 구분이 포함됨
- [ ] `이 문서 요약해줘` 응답 가능
- [ ] 문서 내 단어 존재 여부/횟수 응답 가능
- [ ] 문서에 없는 내용은 `제공된 문서에서는 확인되지 않습니다` 취지로 답변
- [ ] 페이지 번호가 제공된 경우 답변에서 가능한 범위 내 페이지를 언급
- [ ] 기존 PDF 검색/하이라이트/즉시 텍스트 교체 동작 유지

## DOCX
- [ ] DOCX 업로드 후 `documentTextLength > 0`
- [ ] Mammoth 렌더링 DOM에서 텍스트가 중복 없이 추출됨
- [ ] `이 문서 요약해줘` 응답 가능
- [ ] 문서 내 단어 존재 여부/횟수 응답 가능
- [ ] 문서에 없는 내용은 임의로 만들지 않음
- [ ] DOCX는 정확한 페이지 경계가 없는 경우 페이지를 추측하지 않음
- [ ] 기존 DOCX 검색/하이라이트/즉시 텍스트 교체 동작 유지

## 긴 문서
- [ ] 20,000자 이하 문서는 잘리지 않음
- [ ] 20,000자 초과 시 앞 10,000자 + 뒤 10,000자 중심으로 전달
- [ ] 중간 내용이 생략되었음을 프롬프트에 명확하게 표시
- [ ] AI가 전체 문서를 본 것처럼 단정하지 않음
- [ ] 답변에서 필요한 경우 `제공된 일부 내용 기준`임을 알림

## 자동 E2E 범위
`frontend/tests/ai-document-chat.spec.js`에서는 OpenAI 외부 호출을 mock하고 다음을 자동 검증합니다.

1. 문서 없는 상태에서 `/api/chat`의 `documentText`가 빈 문자열인지 확인
2. 테스트용 실제 PDF를 생성/업로드하고 `documentTextLength > 0`, `[1페이지]` 및 PDF 본문 포함 여부 확인
3. 테스트용 실제 DOCX를 생성/업로드하고 `documentTextLength > 0` 및 DOCX 본문 포함 여부 확인
4. PDF/DOCX 상태에서 기존 빠른 문서 작업 버튼 3개가 유지되는지 확인

외부 OpenAI 응답의 의미 품질은 API Key가 없는 CI에서 직접 검증하지 않습니다. 대신 `OpenAiChatServiceTest`로 grounded-answer 지시문과 문서 길이 제한을 검증하고, 실제 API Key가 있는 개발 환경에서는 위 수동 체크리스트로 최종 확인합니다.

# 4차 Tool Calling 설계 메모

3차에서는 아래 intent를 **실행하지 않습니다**. 문서 기반 Q&A 안정화만 수행합니다.

예정 intent:
- `search`
- `highlight`
- `replace`
- `summarize`
- `question_answer`
- `unsupported`

예정 흐름:

1. 사용자가 `테스트를 찾아줘`라고 입력
2. AI가 intent를 `search`로 분류
3. AI는 직접 검색을 실행하지 않고 `정확한 문서 검색을 실행할까요?`와 같은 승인 UI를 제안
4. 사용자가 승인
5. 기존 DocPilot 검색 핸들러 호출
6. 결과를 기존 SearchModal/문서 위치 이동 흐름과 연결

`highlight`와 `replace`도 동일하게 사용자 승인 후 기존 기능을 호출하는 구조를 사용합니다. 특히 `replace`는 원문/변경문과 영향 범위를 사용자에게 보여준 뒤 명시적 승인 없이 실행하지 않는 방향을 권장합니다.
